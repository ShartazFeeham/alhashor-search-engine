# Benchmark: 2-letter vs 3-letter index sharding, substring cap

Date 2026-10-02. Read-only: real `src/search/searchIndex.js` bundled with esbuild into `bench/index.bundle.mjs` (outside the project), run in Node with `globalThis.fetch` replaced by a stub that serves the real files of `public/json`, counts every request, and records order, raw bytes and gzip bytes (zlib.gzipSync default level on the file). Each query/configuration starts a NEW index (cold, as a first visit); the page does `searchTags(words)` (no requireAll: SearchPage.jsx calls `searchClient.search(words)` only, so only requireAll=false is measured) and then `suggest(words, {resultCount})` on the same index, which is what is measured here (`suggest` runs after every search on the page).

## Model and definitions

- **Measured (exact):** result sets and order, number of successful file requests (tags / substring), 404 requests, raw KB (file size on disk), gzip KB (gzipSync of the file, standing in for what the host sends).
- **Modelled:** load time. A discrete-event simulation where the stub resolves each fetch in virtual time: 4 Mbit/s = 500,000 B/s downlink shared equally by the transfers in progress, 150 ms per request before its bytes start (one round trip, no TCP/TLS set-up, no server time), at most 6 requests in flight (extra ones queue), gzip bytes transferred, a 404 costs 150 ms and 0 bytes. The search code issues its requests when earlier ones resolve (own tags file and substring file first, then the tags files of the containing words, then suggest), so the dependency chain is included. CPU time of parsing the response and of the page are NOT in it.
- **CPU ms:** wall time of the awaited `searchTags` call (and of `suggest`) in Node with an instant fetch stub that returns already-parsed JSON (so JSON.parse is excluded, building the per-file Map index is included), cold index per run, median of 5 runs, on this Mac, Node single thread. Machine-specific; phone CPUs are several times slower.
- Files that are missing (404) are decided from the exact names in the folders (not by a normalization-insensitive file system lookup), so the other spelling of য় ো counts as a 404, as on the host.
- "files" = successful (200) requests, tags+substring. "search" = what the result list needs; "suggest+" = extra requests the did-you-mean step adds after it. Time "search" is when the list could be shown, "total" includes suggest.
- 37 queries: 8 common words, 4 rare words (own hadis count of the word itself in the tags index: কাবীর 3, পক্ষেই 8, কিছুমাত্র 15, খচ্চরের 25; the hadis column also counts hadis of longer words containing them), 2/3/4/5-word queries, a 9-word pasted sentence (long-query path: containing words are skipped for words with more than 500 hadis), 6 spelling variants (য় ড় ো in both spellings), a 2-letter word, a 1-letter word, Arabic, Latin, two no-file queries, 8 misspellings (search and then suggest).
